# V1 Final Patch 4 Plan - 2026-06-10

## 目标

Patch 4 收紧 final 阶段的职责边界：final 只做诊断、指出缺口、解释影响并给出补强方向，不替作者生成具体剧情内容。

本轮不运行真实 AI。真实输出效果留给 Patch 4b 小范围回归。

## 问题来源

Patch 3b 的真实回归显示，Sample 01 / 02 的阶段收束、nextStep、项目整理优先级和高解释主题词已经稳定，但三轮输出都仍有具体情节或内容代写倾向。

典型风险包括：

- 建议新增具体过去经历、人物关系或信件内容。
- 建议安排新的场景、动作、阻碍或转折。
- 给出可直接执行的剧情方案，而不是诊断缺口。

## Prompt 约束

- 明确声明“只能做诊断，不能替作者写作”。
- 禁止生成具体桥段、新转折、场景方案、台词、结局、人物动机或人物背景。
- 禁止使用“可以让主角……”“可以安排……”“可以设定……”等代写句式提供具体方案。
- 允许指出规则不清、转折缺铺垫、人物动机缺依据、结构节点薄弱。
- 示例必须是诊断式表达，只说明缺少的功能、原因、压力和后果，不生成情节。

## 建议格式

每条 final 建议继续保留“故事核心修改 / 材料补充 / 项目整理”类别，并固定包含：

1. 问题：指出材料缺口。
2. 影响：说明为什么影响判断。
3. 修改方向：说明需要补强的叙事功能，不提供具体剧情方案。
4. 需要补充的材料：列出作者应补充的信息类型，不替作者写出具体内容。

该格式继续使用现有 `suggestions` / `priority_revisions` 兼容链路，不修改 schema。

## 回归范围

- 新增 Patch 4 静态 prompt 回归脚本。
- 更新现有 final prompt 与 stage prompt 静态测试。
- 保留 Patch 3 的强解释词、`complete_final`、nextStep、项目整理优先级和商业承诺约束。
- 不修改 basic、advanced、gatekeeper、schema、runner、pipeline 或公网入口。

## Patch 4b

Patch 4b 如获单独授权，只复测 Sample 01 / 02 final 输出，重点观察：

- 是否仍生成具体剧情、场景、台词、结局或人物动机。
- 是否稳定使用“问题 / 影响 / 修改方向 / 需要补充的材料”。
- Patch 3 已修复项是否保持稳定。

Patch 4b 前不把本轮静态测试视为真实输出质量结论。
