## 2026-05-19：故事开发诊断系统定位与边界修复

### 1. 系统更名

系统正式更名为：**帧火花故事开发诊断系统**。

### 2. 系统定位升级

从单纯"剧本诊断"扩展为"从创意到剧本的分阶段故事开发诊断"。

支持的材料阶段：

- 故事概念（concept）
- 梗概（synopsis）
- 大纲（outline）
- 人物小传（character_bio）
- 世界观设定（worldbuilding）
- 片段文本（fragment）
- 完整短片剧本（full_script · short）
- 完整长片剧本（full_script · feature）

### 3. 已完成第零层边界修复

- 80–300 字但具备人物、处境、压力/冲突、事件方向的短材料，应优先识别为「故事概念」，不再被误判为梗概后触发 300 字门槛。
- 空泛一句话仍应被打回。
- 有剧本格式不等于「完整剧本」；单场或局部场景应更倾向「片段文本」。
- 完整短片/长片剧本仍能正常进入对应的 `full_script` 路由。

### 4. 已完成 other prompt 分阶段改造

- `other` 不再只是"非剧本材料"，而是「故事开发材料」。
- `concept` / `synopsis` / `outline` / `character_bio` / `worldbuilding` / `fragment` 按不同阶段使用不同诊断标准。
- 长片方向梗概/大纲如果存在核心因果链、反派动机、证据传递、关键反转等主线级问题，不能轻易给「可进入下一阶段评估」。

### 5. 已修复报告术语问题

用户可见报告不再暴露 `concept` / `synopsis` / `fragment` 等内部英文枚举，统一显示中文材料阶段名称（故事概念 / 梗概 / 大纲 / 人物小传 / 世界观设定 / 片段文本 / 完整剧本 / 未明确形态的创意材料）。

### 6. 复测结论

- 《最后的烤冷面》：已能作为「故事概念」进入创意材料诊断。
- 《天台上的宇航员》：已能作为「片段文本」进入创意材料诊断。
- 《沉没的摇篮》：`nextStep` 已收紧为「建议继续打磨」。
- 《蜂鸟行动》：表现基本合格。

### 7. 注意事项

**只要改到后端代码或 prompt（materialRouter / guard / routes / aiClient / diagnosisPipeline / prompts），页面复测前必须重启 diagnosis-api 后端服务**，否则会继续跑旧内存代码。

## 6. 诊断系统当前流程

入口：

```text
POST /api/diagnosis
```

流程：

1. `routes/diagnosis.js`
   - 接收上传文件。
   - 归一化 `materialType`。
   - 调用文件解析、字数守门、诊断流水线。

2. `fileParser.js`
   - 当前实际支持 `.txt` / `.docx`。
   - 不支持 PDF。
   - 不保存上传文件副本。

3. `guard.js`
   - 检查空文本。
   - 检查最小字数 `800`。
   - 检查最大字数 `80000`。

4. `diagnosisPipeline.js`
   - 先跑基础诊断。
   - 如果 `basicReport.nextStep` 以 `可进入进阶诊断` 开头，则进入进阶诊断。
   - 返回：
     - `internalStage`
     - `basicReport`
     - `finalReport`

5. `aiClient.js`
   - 构造 prompt。
   - 调用 DeepSeek / OpenAI 兼容接口。
   - 要求 JSON 输出。
   - 解析失败或关键字段缺失时重试一次。

6. `reportParser.js`
   - 提取 JSON。
   - 规范化字段。
   - 检查 `nextStep` 前缀。
   - 将 warning 放入 `_warnings`。

7. `diagnosisLogger.js`
   - 诊断成功后写入本地日志。
   - 写日志失败只 `console.warn`，不影响用户拿到报告。

## 7. 报告结构

所有诊断报告统一六字段：

```text
summary
core
strengths
problems
suggestions
nextStep
```

其中：

- `strengths`
- `problems`
- `suggestions`

必须是数组。

前端只展示：

```text
finalReport
```

前端不展示：

- `basicReport`
- `advancedReport`
- `_warnings`
- `internalStage` 原始值

`internalStage` 仅映射为用户友好文案：

- `basic` -> `故事基础诊断`
- `advanced` -> `剧本深化诊断`

## 8. 材料类型

当前支持三类：

- `short`：短片剧本
- `feature`：长片剧本 / 网络电影
- `other`：大纲 / 梗概 / 故事概念 / 人物小传 / 世界观设定 / 片段文本等

未知类型在后端归一化为：

```text
other
```

前端上传区当前文案：

```text
支持 TXT / DOCX，文件大小不超过 10MB。
```

这与后端实际能力一致。

基础诊断：

- 文件：`diagnosis-api/src/prompts/basicDiagnosis.js`
- 当前按 `short / feature / other` 分材料类型。
- 短片基础诊断已校准：保留叙事模式识别，但核心仍是判断「这是不是一个故事」。

短片进阶诊断：

- 文件：`diagnosis-api/src/prompts/advancedShortDiagnosis.js`
- 已支持更通用的短片判断框架：
  - 行动目标型

  - 观察型
  - 情绪流型

  - 概念型
  - 荒诞反讽型
  - 循环重复型
  - 社会议题型

长片进阶诊断：

- 文件：`diagnosis-api/src/prompts/advancedFeatureDiagnosis.js`
- 重点是主线贯穿、目标驱动力、冲突升级、中段结构、关键转折、结尾回应和长片体量支撑。

其他创意材料进阶诊断：

- 文件：`diagnosis-api/src/prompts/advancedOtherDiagnosis.js`
- 重点是材料形态、故事前提、人物发展空间、冲突展开可能、设定落地和开发方向。

终极诊断：

- 未接入。

## 10. nextStep 前缀

基础诊断常见前缀：

- `建议继续打磨`
- `需要大改`
- `可进入进阶诊断`
- `建议补充材料`
- `不适合按长片诊断`
- `不适合按创意材料诊断`

进阶诊断常见前缀：

- `建议继续打磨`
- `需要结构性重写`
- `可进入下一阶段评估`
- `暂不适合继续深化`
- `需要重新开发`
- `建议补充材料`

当前 pipeline 只根据基础诊断里的：

```text
可进入进阶诊断
```

决定是否进入进阶诊断。

进阶诊断即使返回：

```text
可进入下一阶段评估
```

也不会继续进入终极诊断，因为终极诊断还未开发。

## 15. 已知风险和注意事项

1. PDF 未接入

前端和后端当前都应保持 TXT / DOCX / 10MB。不要写 PDF 支持文案，除非后端真正接入 PDF 解析。

2. 终极诊断未接入

不要在用户页面或 prompt 中暗示已有终极诊断。

3. 真实 AI 输出仍需样本验证

短片 prompt 已校准，但真实 AI 输出质量仍需用真实样本持续验证。

4. `nextStep` 仍是自然语言前缀

当前 pipeline 依赖 `startsWith('可进入进阶诊断')`。后续更稳的做法是新增结构化决策字段，但当前还未做。

5. 日志只存本地

`diagnosis-api/logs/` 是本地档案库，不会提交 GitHub。切换机器时不会自动同步这些日志。

6. GitHub Pages 不能运行后端

线上 GitHub Pages 只能访问静态官网，不能直接使用诊断 API。诊断系统当前仍是本地 MVP。

## 16. 建议下一步

优先级建议：

1. 用真实短片样本验证短片基础诊断和进阶诊断质量。
2. 用 `logs:diagnosis` 和本地日志库沉淀高潜、边界、异常样本。
3. 继续微调基础诊断和进阶诊断 prompt，但每次只改一个材料类型。
4. 考虑新增结构化 `decision` 字段，减少 pipeline 对中文 `nextStep` 前缀的依赖。
5. 之后再考虑 PDF 上传解析。
6. Word / PDF 下载报告后置，当前已有复制和 Markdown 导出作为轻量方案。
