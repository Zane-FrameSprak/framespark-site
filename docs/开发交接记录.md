## 当前架构原则

- 首页骨架放在 `index.html`
- 视觉样式放在 `css/style.css`
- 首页内容数据放在 `js/site-data.js`
- 页面交互放在 `js/main.js`
- 后续常改内容尽量不写死在 HTML 中
- 项目、平台、生态优先通过数据新增

## AI 协作方式

- GitHub 仓库是 Mac / Windows / Claude Code / Codex 之间的唯一同步源。
- Claude Code 和 Codex 不共享聊天记忆，只共享仓库中的代码、文档、提交记录和远程分支状态。

## 诊断 Prompt 设计记录

### 基础诊断 Prompt（第一版）

文件：`diagnosis-api/src/prompts/basicDiagnosis.js`
状态：✅ 第一版已完成（2026-05-16，Claude Code 编写）

**诊断层级定位：**
基础诊断 = 第一层 = 快速诊断，核心问题：「这是不是一个故事？」

**判断维度（5个）：**
1. 主角：是否有明确欲望或目标的主角
2. 冲突：是否有阻止主角的对立力量或困境
3. 情节骨架：是否有基本的起承转合
4. 人物动机：主角行动是否有逻辑依据
5. 故事内核：是否有可归纳的主题或表达

**输出结构（JSON 6字段）：**
- `summary`：一句话整体判断
- `core`：主角 / 欲望 / 阻力三要素是否成立
- `strengths`：具体亮点数组（真有才写，不凑数）
- `problems`：具体问题数组（最多4条，按重要程度排序）
- `suggestions`：可操作修改建议数组
- `nextStep`：综合判断 + 最优先问题

**设计原则：**
- 不打分，用文字判断代替数字
- 引用剧本具体情节/角色/场景作为依据
- 材料类型区分：简单材料侧重骨架，完整剧本要求引证
- 不足以判断时直接说明，不猜测

**下一步（充值后）：**
在本机 `.env` 填入 `DEEPSEEK_API_KEY`，用几份真实剧本测试输出质量，根据结果打磨 prompt 细节。
