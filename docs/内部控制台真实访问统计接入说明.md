# 内部控制台真实访问统计接入说明

本文档用于说明 FrameSpark 内部控制台后续如何接入真实 Nginx 访问日志。当前目标是生成只读的 `traffic-summary` JSON，供内部控制台读取，不把日志或摘要放到公网目录。

## 为什么不能用 mock 数据

内部控制台用于判断网站运营状态。如果默认展示 mock 曲线或 mock 汇总数字，会误导判断：

- mock 访问量不能代表真实访客。
- mock 404 / 5xx 不能代表真实错误。
- mock 独立 IP 不能用于判断用户规模。
- 未接入真实数据时应显示“— / 待接入真实日志”，不能用 0 或 mock 数字替代。

只有真实数据源已接入且统计结果为 0 时，页面才应显示 0。

## 真实数据来源

真实访问数据来自腾讯云服务器上的 Nginx 日志：

```text
/www/wwwlogs/framespark.cn.log
/www/wwwlogs/framespark.cn.error.log
```

第一版使用仓库脚本：

```text
scripts/nginx-traffic-summary.js
```

该脚本应复制到服务器或随部署包放到服务器后运行。它只读日志，不修改 Nginx，不重启服务，不清空日志，不读取 `.env`，不接入腾讯云 API。

## 统计口径

### 全部请求 allRequests

所有可解析的 Nginx 请求行。它包含：

- 外部用户访问
- Zane 自己访问
- Codex / 本地测试请求
- 搜索引擎和爬虫
- 扫描器和异常探测
- 静态资源请求

因此，全部请求不能直接等同于真实用户行为。

### 页面访问 pageViews

在全部请求中排除静态资源后的 `GET / HEAD` 页面类请求。

静态资源包括：

```text
.css .js .png .jpg .jpeg .gif .svg .ico .webp .woff .woff2 .map .txt .xml .webmanifest
```

`robots.txt` 和 `sitemap.xml` 在 v1 中会因为 `.txt / .xml` 后缀被归为静态或机器读取类请求，不作为普通页面访问判断。

### 疑似有效页面访问 validPageViews

`validPageViews` 是比 `pageViews` 更保守的指标，表示已知站内页面访问。它必须同时满足：

- 请求方法是 `GET / HEAD`
- 不是静态资源
- 不属于 suspicious
- 路径属于已知站内页面

v1 只允许以下路径进入 `validPageViews`：

- `/`
- `/index.html`
- `/diagnosis`
- `/diagnosis/`
- `/talent`
- `/talent/`
- `/projects/`
- `/projects/...`
- `/about`
- `/about/`
- `/contact`
- `/contact/`

`pageViews` 只是粗筛页面请求，仍可能包含扫描、随机路径和异常探测。控制台默认应优先看 `validPageViews` 和具体页面访问，不要把 `pageViews` 直接当作真实用户行为。

以下路径会被排除出 `validPageViews`，并按规则计入 suspicious：

- `/.git`
- `/.env`
- `/.aws`
- `/.azure`
- `/.config`
- `/.circleci`
- `/wp-admin`
- `/wp-login`
- `/phpmyadmin`
- `/version`
- `/v1`
- `/grpc`
- `/mailto:`
- `mstshash`
- 随机短路径，例如 `/aab9`、`/uOXA`
- CONNECT 目标或纯端口路径，例如 `443`、`www.google.com:443`

包含凭证或配置探测关键词的路径也会计入 suspicious，例如：

- `credentials`
- `token`
- `config.yml`
- `accessTokens`
- `azureProfile`
- `application_default_credentials`

也会标记明显扫描器或脚本类 User-Agent，例如：

- `Palo Alto`
- `Go-http-client`
- `masscan`
- `zgrab`
- `curl`
- `python-requests`
- `bot`
- `spider`
- `crawler`

注意：疑似扫描仍然是真实请求，会计入 `allRequests`，但不应当作有效用户行为。

`topValidPaths` 只能基于 `validPageViews` 统计，不应出现 `/.aws`、`/.azure`、`/.config`、`/.circleci`、`/.git`、`/.env`、`/mailto:`、`/v1`、`/grpc` 或随机未知路径。

## 独立 IP 不等于真实人数

`uniqueIps` 只表示日志中出现过多少个不同 IP，不等于真实人数：

- 同一个人使用手机流量和电脑 Wi-Fi，可能被统计为多个 IP。
- 多人共用同一办公室、家庭或校园网络，可能只统计为一个 IP。
- 云服务器、爬虫、扫描器也可能贡献独立 IP。

后续如果需要更接近真实用户数，需要结合 Cookie、会话、行为路径和内部测试过滤；当前 v1 不做。

## 数据污染来源

第一版统计应默认承认以下数据污染：

- 自己访问正式站
- Codex 检查或浏览器测试
- 搜索引擎抓取
- 扫描器探测
- 静态资源加载
- 异常请求和 400 / 404 / 5xx

因此，当前重点是区分数据层级，而不是直接给出“真实用户数”。

## 如何在服务器上运行

示例：统计指定日期并写入摘要文件：

```bash
node scripts/nginx-traffic-summary.js \
  --access-log /www/wwwlogs/framespark.cn.log \
  --error-log /www/wwwlogs/framespark.cn.error.log \
  --date 2026-05-25 \
  --output /home/ubuntu/framespark-reports/traffic-summary-2026-05-25.json
```

统计今天：

```bash
node scripts/nginx-traffic-summary.js \
  --access-log /www/wwwlogs/framespark.cn.log \
  --range today
```

统计昨天：

```bash
node scripts/nginx-traffic-summary.js \
  --access-log /www/wwwlogs/framespark.cn.log \
  --range yesterday
```

统计近 7 日或近 30 日：

```bash
node scripts/nginx-traffic-summary.js \
  --access-log /www/wwwlogs/framespark.cn.log \
  --range last7
```

```bash
node scripts/nginx-traffic-summary.js \
  --access-log /www/wwwlogs/framespark.cn.log \
  --range last30
```

`last7 / last30` 在 v1 中只基于当前单个日志文件中能读到的日期汇总。如果历史日志不足，输出的 `meta.partial` 会是 `true`。

## 输出位置

建议输出到服务器非公网目录：

```text
/home/ubuntu/framespark-reports/
```

不要输出到：

```text
/www/wwwroot/framespark.cn/
```

原因：

- 访问摘要仍属于内部运营数据。
- 即使已脱敏，也不应默认公开。
- 后续内部控制台应通过 SSH 或其他受控方式读取摘要，而不是从公网直接访问。

## 输出 JSON 主要字段

脚本输出结构包括：

- `generatedAt`
- `source.accessLog`
- `source.errorLog`
- `range.type`
- `range.startDate`
- `range.endDate`
- `meta.isRealData`
- `meta.usesMockData`
- `meta.partial`
- `summary`
- `hourly`
- `daily`
- `topPaths`
- `topValidPaths`
- `statusCodes`
- `methods`
- `suspiciousSamples`

核心指标包括：

- `allRequests`
- `uniqueIps`
- `staticAssetRequests`
- `pageViews`
- `validPageViews`
- `suspiciousRequests`
- `homeViews`
- `diagnosisViews`
- `talentViews`
- `projectViews`
- `notFound`
- `badRequests`
- `methodNotAllowed`
- `serverErrors`
- `parseFailed`

## 隐私处理

脚本输出遵循以下原则：

- 不输出完整 IP 列表。
- `suspiciousSamples` 中的 IP 会脱敏，例如 `123.123.xxx.xxx`。
- 不输出完整原始日志全文。
- 不输出大量完整 User-Agent。
- 不读取 `.env`。
- 不打印密钥。

## 后续控制台接入方式

内部控制台后续可以读取 `traffic-summary` JSON：

1. 服务器定时运行脚本，生成 `/home/ubuntu/framespark-reports/traffic-summary-YYYY-MM-DD.json`。
2. 本机内部控制台通过只读 SSH 读取摘要文件。
3. 控制台将摘要映射到当日 / 昨日 / 近 7 日 / 近 30 日图表。

接入前，控制台仍应显示“待接入真实日志”，不能用 mock 或 0 顶替。

## 后续可扩展口径

后续可以增加：

- `allTraffic`
- `externalTraffic`
- `internalTraffic`
- `botTraffic`

但 v1 不做真实过滤，不配置 IP 白名单，不读取用户真实 IP 明细，也不接入腾讯云 API。
